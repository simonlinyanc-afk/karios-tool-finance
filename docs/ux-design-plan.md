# Kairos-Finance UX 设计计划

**阶段：** Phase 4
**依据：** 《黄鸟发票管理系统 UX 设计与界面文案文档》、当前工作区界面实现、Vercel Web Interface Guidelines

## 1. 设计目标

Kairos-Finance 应呈现为清晰、可信、轻量的工作室内部财务工具，而不是 AI 演示页面。普通用户不需要理解模型、缓存实现或数据结构，也能完成：

1. 上传 JPG、PNG 或 PDF 发票。
2. 看懂每张发票的处理进度与结果状态。
3. 快速处理“建议检查”和“识别失败”的条目。
4. 必要时使用“增强识别”或手动填写。
5. 在导出或打印前知道仍有哪些问题。

## 2. 本阶段边界

### 必须完成

- 上传区明确支持格式、数量、PDF 首页规则与隐私说明。
- 批量处理显示总数、已完成、建议检查、识别失败及当前进度。
- 状态统一为用户语言，不显示工程术语。
- 识别失败提供“重新识别 / 增强识别 / 手动填写”。
- 建议检查项提供“确认无误 / 增强识别 / 手动修改”。
- 表格金额、税额、日期与发票号更易扫描。
- 所有关键操作可用键盘完成，图标按钮具有可访问名称。
- 长列表减少无意义渲染，并为 50 条以上内容启用渲染优化。
- 导出前明确提示建议检查项与失败项。

### 明确保留

- IndexedDB 本地优先数据与 OCR 缓存顺序。
- PDF.js、Web Worker、OffscreenCanvas 与浏览器图片预处理。
- ExcelJS 导出、`print.html` 打印与现有打印任务结构。
- `js/utils/exportManager.js` 中 3 处安全错误提示文案：Excel 生成不可用、打印窗口被拦截、导出失败兜底。
- `/api/ocr`、标准识别、自动再识别与增强识别模式。

### 本阶段不做

- 不迁移 Next.js，不引入完整设计系统或路由框架。
- 不重做设置中心、完整详情侧栏或虚拟列表框架。
- 不改变构建系统、CDN 依赖或部署方式；这些属于 Phase 5-6。
- 不修改 OCR 模型路由、Schema、缓存键或财务字段结构。

## 3. 用户流程与界面状态

### 3.1 上传

主文案：`拖入发票，自动整理报销明细`

辅助说明：`支持 JPG、PNG、PDF。单次最多 10 个文件，PDF 默认识别第 1 页。`

隐私说明：`系统会先在浏览器中压缩图片，再发送用于识别；原始文件不会保存在服务器。`

上传区本身使用 `<button>` 或具备等价键盘行为的语义控件。隐藏文件输入有明确 label；取消单项和取消全部都有可访问名称。

### 3.2 批量处理

总览固定显示：

- 本批次 N 张发票
- 已完成 N 张
- 建议检查 N 张
- 识别失败 N 张

单项状态依次使用“等待识别”“正在准备图片”“正在识别”“已完成”“建议检查”“识别失败”“已取消”。进度变化通过 `aria-live="polite"` 告知辅助技术；动画尊重 `prefers-reduced-motion`。

### 3.3 表格检查

- 状态列始终可见。
- 日期显示为统一的 `YYYY-MM-DD`，编辑仍使用日期控件。
- 金额、税额、价税合计右对齐，保留两位小数并使用等宽数字。
- 发票号使用等宽字体并允许复制。
- 行预览、排序、删除、附件操作全部使用按钮语义与可见焦点。
- “建议检查”字段在展开区域中列出具体原因，不用内部 warning code。

现有 `ReimbursementTable` 是本阶段的 InvoiceTable；现有展开行承担轻量 ReviewPanel 职责。本阶段不新建独立侧栏，以避免大规模改写。

### 3.4 识别恢复路径

| 当前状态 | 主操作 | 其他操作 |
| --- | --- | --- |
| 已完成 | 保存修改 | 快速检查后导出 |
| 建议检查 | 确认无误 | 增强识别、手动修改 |
| 识别失败 | 重新识别 | 增强识别、手动填写 |
| 手动修改 | 保存修改 | 恢复识别结果（若有） |

自动复查只显示“系统已自动再识别一次”。用户主动触发的高精度模式只显示“增强识别”。从 OCR cache 或历史快照恢复时只显示“已从本地记录恢复”。

### 3.5 导出与打印

导出预览使用同一状态词，并显示尚未处理的数量：

- `还有 2 条发票建议检查。` 按钮：`先去检查 / 仍然导出`
- `有 1 条发票未完成识别。` 按钮：`查看失败项 / 仍然导出`

打印入口提示：`即将打开打印页面。你可以直接打印，或选择“另存为 PDF”。`

### 3.6 设置

本阶段不新建完整 SettingsPanel。现有系统弹窗与列设置只统一命名、键盘行为和本地数据说明。完整设置中心在后续阶段按以下分组实现：识别设置、本地数据、导出与打印、系统状态。

## 4. 组件与文件边界

### 原子纳入的 UI 运行基线

以下当前文件存在相互依赖的既有改动，Phase 4 应以当前完整文件为基线进行小步修改并整体验证：

- `index.html`
- `js/components/UploadZone.js`
- `js/components/ReimbursementTable.js`
- `js/components/ExportPreviewModal.js`
- `js/components/SystemModals.js`
- `js/components/AppHeader.js`
- `js/components/icons.js`
- `assets/Kairos Finance.svg`
- `assets/Kairos Logo.svg`

`ExportPreviewModal` 使用的图标注册、`index.html` 的事件接口、表格与系统弹窗的 props 已形成当前运行基线。只暂存少数新 hunk 会产生与当前页面不同、无法独立验证的提交快照。

### 窄范围兼容修改

`print.html` 只考虑纳入 Dexie v5 schema 兼容 hunk与安全打印错误文案 hunk，使打印页能够打开已由 `storageRepository.js` 升级到 v5 的数据库，并在加载失败时给出“返回主页面重新打开打印预览”的下一步。打印页品牌、title、图片等待、布局样式和其他既有修改不并入本阶段。

`js/utils/exportManager.js` 只纳入 3 处安全错误提示文案，覆盖 Excel 生成不可用、打印窗口被拦截与导出失败兜底；导出结构、Excel 数据、图片处理和打印任务 payload 不并入本阶段。

### 排除

- `README.md`、`package.json`：Phase 5-6。
- `js/utils/imageProcessor.js`：图像预处理与 Phase 7 回归范围。
- `js/utils/exportManager.js` 非文案逻辑：导出结构、Excel 数据、图片处理和打印任务 payload。
- `PDFTemplate.js` 与黑色 Logo 资源：不属于本阶段主流程修复。
- 混合历史测试 `tests/ocr-core.test.js`、`tests/self-hosting.test.js`：保持未跟踪，不纳入 Phase 4。

## 5. 实施顺序

1. 写入文案常量和状态映射测试，先让旧文案断言失败。
2. 修复 UploadZone 语义、状态、隐私说明与 reduced motion。
3. 修复批量总览和 toast；禁止原始 error.message 直接进入 UI。
4. 统一表格 Badge、金额格式、日期、发票号和键盘预览。
5. 在行操作中接入重新识别、增强识别和手动填写路径。
6. 统一导出预览、系统弹窗和弹窗关闭按钮。
7. 增加长列表 `content-visibility` 与必要的 memo/稳定回调；不引入新依赖。
8. 验证打印 v5 兼容、Excel、PDF、缓存、批量取消和增强识别。

## 6. 性能策略

- 批量队列更新使用函数式 setState，只替换发生变化的对象。
- 避免在同一 render 中重复计算批次统计；使用一次遍历的派生摘要。
- 复用稳定的状态映射、格式化器和正则表达式。
- 表格行使用稳定 key；对 50 条以上行启用 `content-visibility: auto` 与合理 intrinsic size。
- 只有在 props 可保持稳定时才使用 `React.memo`；不为简单表达式滥用 `useMemo`。
- 不在 Phase 4 引入虚拟列表依赖。

## 7. 验收标准

- 主界面用户文案不出现 fallback、schema、JSON、MD5、IndexedDB、DashScope、model、OCR 失败、缓存命中等工程表达。
- 每个失败状态同时说明问题和下一步操作。
- 仅使用键盘即可完成上传、取消、排序、展开、预览、重新识别、增强识别、手动填写与关闭弹窗。
- 图标按钮具有 `aria-label`，异步进度具有 `aria-live`，焦点状态可见。
- 金额与税额右对齐、两位小数、等宽数字；发票号等宽；日期格式一致。
- 10 文件批量流程状态准确；50/100 行表格滚动和编辑无明显卡顿。
- OCR cache 命中仍优先于网络；增强识别仍绕过本地恢复并刷新缓存。
- Excel 导出与 `print.html` 打印可用；PDF 仍只识别第一页且给出说明。
- 自动化测试、真实浏览器键盘路径和视觉检查全部通过后才提交。
